# AGENTS.md — animation

## What this is

An anamorphic particle animation. `index.html` is one self-contained WebGL2 page.

A cloud of glowing particles drifts in the air. It hides six messages, each readable from its own secret viewpoint, its eye; from everywhere else it looks like a plain cloud. In sequence order, with each eye's azimuth and elevation:

- "hello" above "world", at (38°, 14°);
- a smiling face, at (98°, 18°);
- "What", at (158°, 16°);
- "a", at (218°, 20°);
- "beautiful", at (278°, 16°);
- "world", at (338°, 18°).

The words lean right 14°; the face stands upright.

The viewer changes the angle by dragging. At load a camera tour glides to each eye in sequence order, holds there 3 s and stops at "world". Play replays the sequence and "Find the angle" glides to the next message. `#capture` hides the controls, the cursor and the focus outline and loops the sequence for screen recording; only Escape ends it. README.md says how to open and record it.

Non-goals: build steps, frameworks, runtime dependencies, server code.

Stack: plain HTML, CSS and JavaScript on WebGL2. Node 24 (`.nvmrc`) is for dev tooling only. Playwright (a dev dependency) drives headless Chromium for screenshots and gates.

The design and acceptance records are `docs/work/0_hello-world-cloud/plan.md` (hello world) and `docs/work/1_sentence-sequence/plan.md` (the six messages, the sequence and capture mode).

This repo's own rules: [docs/policies/local-rules.md](docs/policies/local-rules.md).

For the six messages, `npm test` ran again on 2026-10-15 and 2026-10-21, the mutation proof on 2026-10-15, and the `seq` and `between` shoot presets on 2026-10-21. For repair round 1 (R1a), `npm test`, the mutants it added or touched and both presets ran on 2026-10-22.

- `npm ci` installs the one dev dependency, Playwright 1.63.0 (pinned). It installs no browser, because neither `playwright` nor `playwright-core` has an install script.
- `npx playwright install chromium` then puts that version's Chromium (153.0.8010.12) in the local Playwright cache. When the build is already there it reuses it and downloads nothing (2 s here). The gates use only that cache; nothing downloads at test time.
- `npm test` runs the headless suite through `tests/run.mjs`: 45 tests in 2.5 to 3 minutes (153.6, 157.5 and 158.9 s over three runs on 2026-10-22; an earlier green run that day took 172.1 s).
  - It runs `tests/illusion.test.mjs` alone first, then `tests/sequence.test.mjs` beside only the hygiene scan, which opens no browser, then the other `tests/*.test.mjs` files two at a time, because SwiftShader WebGL2 is CPU-heavy (`tests/lib/phases.mjs`). So the timing checks, the font-hang loads and the control fling, never run beside the illusion file's renders or the sequence file's pages.
  - Beside the sequence file the font-hang check failed once: its load with the stylesheet answered took 2.7 s and the one with it hung 6.1 s, 1.4 s past its 2 s margin (2026-10-22). In the third phase they took 0.37–0.52 s and 0.40–0.57 s over four runs.
  - `tests/sequence.test.mjs` opens five browsers of its own and keeps up to six pages drawing in them for about 55 s: 390×300 pages for the camera's path, which it checks from a log of every frame, not from reads at set times, and 640×400 pages for the pictures at the sequence's holds.
  - The illusion file queues most of its views at start and renders up to four at a time in four browsers, because each browser draws all its pages in one GPU process. `pump()` hands each 1280×800 view to the next browser in turn without checking which one is free, so two can render in one browser at once; every 390×844 view renders in browser 0 and every blank-readback view in browser 1. The seed test renders outside the queue. The camera-mode test times its shots, so it runs last: it pauses `pump()` and waits for the renders in flight, so no queued view renders beside its two pages.
  - It exits 1 when a test fails, a file fails to load or no test passed. `PAGE=<path relative to the repo root>` runs it against another copy of the page.
- `npm audit --audit-level=high` runs after any dependency change.
- `npm run shoot -- --preset=<name>` is the visual instrument; the header of `scripts/shoot.mjs` lists its options. `magic` shoots hello world at its eye E, `off` the views around E, and `all` both. `seq` shoots every message at its own eye, and `between` the views away from the eyes: the midpoints, each eye's back view, above, below and the start view. It also takes single views. It saves PNGs under `tmp/shots/` and prints each one's sha256 and what the page reports. A visual change still needs someone to look at the shots at native resolution; the gates do not replace that.
- `node tests/mutate.mjs [name ...]` re-proves the gates.
  - It first runs the gate files on the real page and tree as a control, and stops with exit 2 unless every test passes.
  - It then writes each mutant under `tmp/mutants/` and runs the gates against it, in the phases `npm test` uses. Each red test prints as CHECK (an assertion failed, an `until` timeout included) or ERROR (anything else, such as a browser that does not launch), with its test-file line.
  - A page that never becomes ready is an ERROR in every test that needs a drawn page, because each one waits through the harness, which throws a plain Error. That includes the font-hang test, whose baseline load waits that way. The no-WebGL2 test is the exception: a page whose script never runs shows no message there, a CHECK, but then no test passes, so the mutant is flagged.
  - A mutant counts as killed only by a CHECK. One with only ERRORs is "errored". One with 0 green tests is flagged, since it may break the page wholesale rather than the one behaviour it names.
  - It exits 1 on any survivor, errored or flagged mutant.
  - Tree mutants are copies of the repo without `.git`, `node_modules`, `tmp`, test output and `.claude/worktrees`, so any file a command names is there too. Each is deleted once scanned.
  - Run it after changing a gate or the page. It holds 91 mutants: 68 page, 23 tree. The last full run, of 81 (58 page, 23 tree), took 176 minutes on 2026-10-15, about 179 s per page mutant, since each runs every page gate file in the phases above. The targeted run for R1a, of its 10 new mutants and the 4 that only the sequence file kills, took 42 minutes on 2026-10-22, about 168 s per page mutant (155–237 s). So run only the mutants a change touches by name, and keep it the only browser workload while it runs.
  - A β 1.0 mutant (`full-relocation`) stays retired: review round 3 (F25) looked for a bound on a three-seed mean that holds β at 0.85 and found none (see Bound below). Until a gate holds it, β stays at 0.85 by decision ([docs/learning/lessons.md](docs/learning/lessons.md)).

  - At each of the six eyes the message's strokes are at least 1.5× brighter than the gaps between them, at 1280×800 and 390×844 (t 0; 1.55–2.08 measured for seeds 1–12). Hello world is also measured at t 7.3 and 31 s, at fov 32 and 80, and when canvas readback returns zeros.

    - The stroke shapes are the same for two seeds (IoU at least 0.65; 0.78–0.91 measured), so they come from the message, not the particle draw.
    - A zoomed view's mask keeps the stroke area the zoom predicts, so it cannot fatten where sprites merge at fov 80.
  - At E at 1280×800 the strokes form two lines, the top one narrower, with a full-height stem at the left end of the top line ("h") and at the right end of the bottom line ("d"). So the text is neither mirrored nor turned 180°.

    - It then measures how far the "h" and "d" stems still lean, along each line's outer ink edge. The mean over seeds 1–3 must be within 4° of upright, so the letters lean 14° ± 4° (0.14° measured; −9.0° with a 5° lean, −13.8° with upright letters).

The page measures 0.157 at most for seed 1 and 0.211 at most for any of seeds 1–12. Flat text measures 0.229 at most there, so this bound alone does not catch it (see Bound).
    - At a neighbour's eye the neighbour's own strokes light some of the mask's pixels, so the excess there includes where the two messages overlap.
    - Hello world is also held at 25° above and below E and midway to its neighbours, to at most 0.15 as a mean over seeds 1–3 (0.066 at most; flat text gives 0.694 at el+25 and 0.382 at el−25).

At each, the text particles carry the light (0.93–1.05) and the colour balance (each channel within 3%) of the same particles drawn as ambient, and at t 0 their sprite size (within 15%).

So the raw per-channel ratio falls to 0.91 in blue at E, and the light ratio to 0.955. The colour check therefore compares each channel's share of the light over the pixels where no channel clips: 0.998–1.001 for seeds 1–6 at every view. A green tint near E (red and blue × 0.739, green × 1.10) and a 30% gold tint fail it.

The hygiene scan's blind spots:
- code assembled at run time: `eval`, strings or names built from pieces, computed keys such as `cp['exec']`, a launch method reached by destructuring;
- a page under a name without "page" that the file does not bind itself, such as a parameter called `tab`, or reaches only through a member or a call;
- Windows PowerShell started as another program's argument rather than where a command starts, such as `cross-env powershell "ii index.html"` or `call powershell …`, unless `-Command` comes before the command;
- programs that open a browser by default but are not named in the scan;
- files of other types, and repo files outside the scanned folders that only code names, such as a path passed to a Node child process;
- files outside the scanned paths that no command names: `docs/`, `tmp/`, `node_modules` and its install scripts, git hooks, `~/.claude`, settings files `.gitignore` names, and agents' scratch scripts outside the repo;
- command starts the scan does not know (review round 6, F47):
  - a one-line PowerShell script block such as `if (Test-Path index.html) { ii index.html }` or `| ForEach-Object { ii $_ }`;
  - cmd's `for %%f in (index.html) do start %%f` and `if exist index.html start index.html`;
  - wrapper commands such as `call start …`, `nohup open …` and `cross-env start …`;
  - a `for…of` loop over a variable that already holds the pages, such as `for (const tab of tabs)` after `tabs = context.pages()`;
- the desktop app's own browser pane, which opened the file in the original incident.

It still flags a few harmless forms, listed in its header: a `pause()` on a non-page receiver whose chain names "page" or on a bound name that holds no page, a program's own `-c` switch before a quoted opener word, a separator inside quoted text before an opener word (`echo "a; open b"`, `echo "(a) else open b"`), an opener word passed as an argument after `powershell -File` and its script, and a launch method's or `child_process`'s name inside a string.

## Invariants & boundaries

- The page stays one self-contained `index.html` that opens straight from disk: no build step, no external scripts, no runtime dependencies. The only external request is the optional Google Fonts stylesheet.
- Every particle renders the same way at every camera angle: text and ambient particles get the same light, colour, size and focus at every eye and everywhere else, and nothing in the scene brightens as the camera nears an eye. The words become obvious only because the particles line up there (owner directive, 2026-10-11: "They need to be glowing consistently no matter what angle. The words should be entirely depending on the right angle to be obvious.").
- The particles are drawn in one additive pass that the test-only layers split exactly: ONE/ONE blending into the 8-bit canvas, no depth buffer, depth of field computed per sprite, and `layer=text` and `layer=ambient` each drawing one of the two ranges the shipped draw covers. `textof=<name>` narrows `layer=text` to one message's part of its range. The alike gate's pixel identity rests on this, and on a renderer that does not dither (SwiftShader; the page leaves WebGL's default dithering on), so a change to the draw that turns it red needs the gate rethought, not its bound loosened.
- Each text particle belongs to one message and moves only along its own sight-line from that message's eye, so its projection from there never changes. Ambient drift plus wobble is at most about 0.52 world units. Seen from an eye that is about 0.33σ at the text plane and less beyond it (σ ≈ 1.58 world units, the relocation width in the plans), but about 0.7σ at the main cloud's near edge, 16.5 units in front of the plane. So the density that hides each message holds closely at and beyond its plane and only roughly in front of it.
- Zoom changes the field of view only. The eye stays on the orbit sphere with world-up roll, because moving it breaks the illusion.
- The letters lean right by `SLANT` (14°), each line sheared about its own baseline. The face stands upright. An elevation turn keeps every particle's screen column, so upright stems would show above and below an eye as vertical streaks; leaning ones spread over many columns. The layout gate undoes the lean before it measures and then holds the stems within 4° of upright, so `SLANT_DEG` in `tests/illusion.test.mjs` changes together with `SLANT`. The streak gate holds the el±25 column residual that the lean is for.
- The six messages, their order, their eyes and the start view are part of the contract (`tests/lib/messages.mjs`; `scripts/shoot.mjs` keeps its own copy of the eyes, `EYES`). Hello world's eye stays at (38°, 14°), and the start view is (8°, −16°). Every eye sits at +14° elevation or higher, because an eye within about 20° of another's antipode sees that message mirrored and radially smeared.
- The test contract changes only together with the gates. Query parameters: `az`, `el`, `fov` (degrees), `t` (freezes the particle clock), `tour=0`, `layer=text|ambient`, `textof=<name>` (with `layer=text`: that message's text particles only), `msg=<name>` (the camera at that message's eye; `az` and `el` override it), `seed`, and the test-only `beta`, a number from 0 to 1 that sets the peak relocation chance for every message (other values keep the default 0.85). The base cloud is the same for every `beta`, and `beta=0` relocates nothing, so a render minus its `beta=0` twin holds only what relocation changed. Read-only `window.__cloud`: `ready`, `frame`, `magic` (hello world's eye), `messages` (`{name, az, el}` in sequence order), `view()`, `alignment()` (degrees from hello world's eye), `mode()` (`tour` for the sequence and capture mode), `target()` (the message the camera holds at or heads for, else null), `capture` (true in capture mode), `counts` (with `byMessage`). DOM ids: `#scene`, `#find`, `#play`, `#readout`, `#hint`, `#nogl`. `#scene` is exposed as a focusable `application` with a role description and a name.
- The sequence glides to each eye in order and holds exactly there. "Find the angle" goes to the next message. `#capture` shows no controls, no cursor and no focus outline and loops the sequence; of the inputs, only Escape ends it. Reduced motion switched on mid-glide in Play or capture mode cuts to that glide's eye at once.
- The page doubles as a claude.ai artifact: one deliberate dark theme with colour tokens on `:root`, no `#key=value` hash state, and it works at 390 px wide. The only hash it reads is the bare `#capture` anchor, which the artifact host passes through.

## Conventions

- Screenshots and other run output go under `tmp/` (ignored) and are deleted once no task needs them.
- To publish the page as an artifact, strip the document wrapper (the doctype, the `html`, `head` and `body` tags, and the charset and viewport metas), because the artifact host supplies them.
