# AGENTS.md — animation

## What this is

An anamorphic particle animation. `index.html` is one self-contained WebGL2 page.

A cloud of glowing particles drifts in the air. It hides six messages, each readable from its own secret viewpoint, its eye; from everywhere else it looks like a plain cloud. In sequence order, with each eye's azimuth and elevation:

- "hello" above "world", at (38°, 14°);
- a smiling face, at (98°, 18°);
- "What", at (158°, 16°);
- "a", at (218°, 20°);
- "beautiful", at (278°, 16°);
- "world", at (338°, 18°).

The words lean right 14°; the face stands upright.

The viewer changes the angle by dragging. At load a camera tour glides to each eye in sequence order, holds there 3 s and stops at "world". Play replays the sequence and "Find the angle" glides to the next message. `#capture` hides the controls, the cursor and the focus outline and loops the sequence for screen recording. Of the inputs, only Escape ends it; changing the anchor in the address ends it too. Escape takes the anchor out of the address, so adding it back starts capture mode again. README.md says how to open and record it.

Non-goals: build steps, frameworks, runtime dependencies, server code.

Stack: plain HTML, CSS and JavaScript on WebGL2. Node 24 (`.nvmrc`) is for dev tooling only. Playwright (a dev dependency) drives headless Chromium for screenshots and gates.

The design and acceptance records are `docs/work/0_hello-world-cloud/plan.md` (hello world) and `docs/work/1_sentence-sequence/plan.md` (the six messages, the sequence and capture mode).

This repo's own rules: [docs/policies/local-rules.md](docs/policies/local-rules.md).

  - Nothing names a system browser, a desktop opener, an opener package or live-reload server (`open-cli`, `live-server`, `lite-server`, `browser-sync`, `npx open`, `http-server -o`), `connectOverCDP`, or a headed, debug, UI, inspector, code-generator, open or report mode (`--headed`, `--debug`, `--ui`, `--open`, `PWDEBUG`, `playwright open` and `playwright@<version> open`, `show-report`). A Playwright config picks no channel.
  - Nothing calls `pause()` on a receiver that can be a page: one whose chain names "page", or a name that can hold one.
    - A name can hold a page when the file declares it from a statement that calls `newPage`, `pages()` or `waitForEvent`, alone or in a destructuring pattern, as in `const [popup] = await Promise.all([page.waitForEvent('popup'), …])`. A declaration nested in another, such as an arrow helper's first statement, and each declaration in code without semicolons count on their own.
    - It can also when the file binds it as the variable of a `for…of` loop over such a call, as in `for (const tab of context.pages())`. Only the iterable counts, up to its first `)`, so a page opened in the loop body does not bind the loop variable.
    - It can also when the file assigns it, awaited or not, from a bare name that can hold a page or names "page", as in `const popup = await popupPromise`.
    - Pauses on sockets, requests, streams, media and animations pass.
  - No shell command runs an opener where a command starts: at a line start, after `;`, `&`, `|`, `(` or a backtick, or after `cmd /c`, `sh -c` (or `-lc`) or `-Command`. The command word may be quoted there; a quote anywhere else is text, as in `echo "open tasks: 3"`.
    - cmd's echo-off `@` and the keywords `then`, `do`, `else` and `exec` may come first there, as in `@powershell -NoProfile "ii index.html"` in a `.cmd` file or `if …; then start index.html; fi`. cmd's `) else` starts a command too.
    - Windows PowerShell started where a command starts runs its first argument that is not a switch or a switch's value as a command. So after `powershell` or `powershell.exe` there and its switches, whose values may be quoted (`powershell -WindowStyle "Hidden" "ii index.html"`), the next word counts as a command start too.
    - The word `powershell` anywhere else is text, as in `git commit -m "fix powershell start script"`.
  - Only Playwright code builds `file:` URLs, including from `import.meta.url` outside `fileURLToPath`.
  - Child processes start only Node, in files and in commands such as `node -e`, whether `child_process` is imported whole, by name, renamed or destructured.

Bound: one engine, headless Chromium 153 with SwiftShader WebGL2, device pixel ratio 1 for the image gates, and only the listed views, times, seeds, `beta` values and inputs. The exact pixel identities rest on SwiftShader's 8-bit additive blending without dithering. The image gates measure light, colour and shape, not whether a person can read the text.
- The legibility of the five messages after hello world is measured only at t 0, seed 1 and the default zoom; their layout, zoom and readback behaviour are not.
- The hiding gate looks at the listed views only: the eyes, the midpoints, the antipodes, three far views and hello world's el±25. A message legible only between them would pass, and so would shape too fine or too faint for its seed-8 stroke mask. At the eyes and midpoints it reads one seed.
- The colour check leaves out the pixels where a channel is at 255, at most 8% of each image's lit pixels, but at E they hold 32% of the text layer's light. So a colour change confined to them would pass.
- Each message's own particles are compared for light only, at β 0.2. A colour or size change confined to one message's particles is checked only through the whole text layer, which dilutes it by that message's share.
  - Their light band, 0.95–1.12, passes a change in one message's particles alone of up to 6.1% brighter ("beautiful", whose ratio sits highest, 1.056 for seed 1) to 10.1% ("a"), and up to 6.8% dimmer (hello world) to 10.0% ("beautiful"). The whole text layer at the eye then reads 0.950–0.997, inside its own band, for changes from 0.88× to 1.15× (seed 1; review round 1, F85).
- The light band allows a reveal of about 8% at E, where the cap holds the ratio at 0.97: text 1.08× brighter near E reads 1.038 there.
- The scene-light bound at the eyes catches a glow of the whole scene near an eye from 5.5% at hello world's eye, whose ratio sits lowest (0.980 for seed 1), and from 3.1–4.8% at the other eyes; a smaller one passes. Those figures are for a glow that fades out by 12°; a wider one passes as far as it also lights the midpoints beside the eye.
- A reveal confined to angles between the measured views (for example only 5–10° from an eye) would pass them.
- So would one shown only while the camera moves (mid-glide, mid-snap, mid-tour or coasting), since every view is shot with the camera at rest or in a hold, or only once an eye is reached another way (a snap, the arrow keys, or "Find the angle" from elsewhere than the eye before). "Find the angle" landings are pictured after two histories only: from the eye before, on a page with `tour=0`, and after the load tour has played to its end at "world", on the tour page. A reveal that needs another history passes: "Find the angle" clicked during the load tour, during or after Play or capture mode, or after a drag, a key, a zoom or a snap; and on the tour page, whose landings are shot on arrival only, a reveal after the camera has rested at a landing a while (review round 2, F88). The illusion file's camera-mode shots cover hello world's eye; the sequence file's cover the holds below, the tour's end at "world", the "Find the angle" landings at all six eyes after it and the landings at the five later eyes from the eye before.
- So would one at the sequence's holds that the sequence file does not shoot: Play's and the load tour's holds other than the face's (the illusion file shoots the load tour's hold at hello world), and capture mode's later passes. Play is pictured once, clicked where the tour ended at "world"; Play from a view set by URL is checked for its path only.
- So would one that waits longer than the dwells measured: 8 s idle after a "Find the angle" landing at each eye and after the tour ends at "world", and about 1.5 s into the tour's first 3 s hold at E (at least 1.5 s, as checked), so a reveal in the rest of that hold passes. Each sequence picture is likewise shot about 1.5 s into its 3 s hold, so a reveal in a hold's first 1.5 s or after the shot passes too. A hold shot that misses its hold is retried only in capture mode, once, on the loop's next pass; a miss at the tour's or Play's hold at the face, or a second miss in capture mode, fails the run as an error, so a loaded machine can fail `npm test` there without a page defect (F93).
- So would one driven by the particle clock: every shot freezes it with `t`, which the shipped page never sets.
- So would one shown only on a URL without `t`, as a visitor's is: every image gate sets `t`, and every one but the tour shots (with the tour's end at "world" and Play there) and capture mode's pictures sets the view too (`az` and `el`, or `msg`).
- So would one in every draw that stays inside each band on its own: light within 0.93–1.05, each colour channel's share within 3%, sprite size within 15%. The exact ties catch only what the shipped draw, a camera mode or a dwell at E adds.
- Nor do they hold β at 0.85 (review round 3, F25; the lesson is in [docs/learning/lessons.md](docs/learning/lessons.md)). The measure is the az+25 row residual over the cloud's own noise, as a mean over three seeds, measured on the hello-world-only page of work unit 0.
  - β 0.85 measured 1.416, 1.693, 1.556 and 1.524 for seeds 1–3, 4–6, 7–9 and 10–12. β 1.0 measured 1.637 for seeds 1–3 and 1.897 for seeds 4–6.
  - Per seed (1–6), β 1.0 changed it by −0.3% to +37%, +14% on average.
  - So no bound on a three-seed mean tells them apart: β 1.0 at seeds 1–3 lies inside β 0.85's own range. A mean over about 12 seeds would, at about four times the illusion file's cost.

The page gates have their own bounds:
- The budget check reads the particle count and the sprite fill at the default zoom only, at the start view and the six eyes. Zoomed all the way in at E, the sprites cover about 13.6× the screen (112 M px a frame at 1920×1080 and DPR 2), and no gate bounds that.
- It cannot show a real GPU's frame rate. It counts the pixels the sprites cover, not shading or memory cost, and SwiftShader allows points up to 320 device px here, where a real GPU may cap them lower. It measures only points drawn with `drawArrays`, by a page that draws from `requestAnimationFrame` callbacks, in one animation frame at each view.
- The 390 px check reads local fonts on Windows: the browser's monospace fallback and Courier New for the stand-ins. DM Mono's own file is not available offline, so its widths are assumed to be 0.600 em, as most monospace fonts' are. A web font wider than about 0.603 em would cut the widest readout short, as the 0.660 em case shows, but cannot push the buttons out of the bar.
- The anchor check goes to the address with `#capture` from the test, as a viewer's address bar would; a real host's address bar, and its history rules beyond a `replaceState` and `pushState` that throw, are not tested.

No screen reader was available, so the accessibility check reads Chromium's tree, not what NVDA or JAWS do with it.

The hygiene scan's blind spots:
- code assembled at run time: `eval`, strings or names built from pieces, computed keys such as `cp['exec']`, a launch method reached by destructuring;
- a page under a name without "page" that the file does not bind itself, such as a parameter called `tab`, or reaches only through a member or a call;
- Windows PowerShell started as another program's argument rather than where a command starts, such as `cross-env powershell "ii index.html"` or `call powershell …`, unless `-Command` comes before the command;
- programs that open a browser by default but are not named in the scan;
- files of other types, and repo files outside the scanned folders that only code names, such as a path passed to a Node child process;
- files outside the scanned paths that no command names: `docs/`, `tmp/`, `node_modules` and its install scripts, git hooks, `~/.claude`, settings files `.gitignore` names, and agents' scratch scripts outside the repo;
- command starts the scan does not know (review round 6, F47):
  - a one-line PowerShell script block such as `if (Test-Path index.html) { ii index.html }` or `| ForEach-Object { ii $_ }`;
  - cmd's `for %%f in (index.html) do start %%f` and `if exist index.html start index.html`;
  - wrapper commands such as `call start …`, `nohup open …` and `cross-env start …`;
  - a `for…of` loop over a variable that already holds the pages, such as `for (const tab of tabs)` after `tabs = context.pages()`;
- the desktop app's own browser pane, which opened the file in the original incident.

It still flags a few harmless forms, listed in its header: a `pause()` on a non-page receiver whose chain names "page" or on a bound name that holds no page, a program's own `-c` switch before a quoted opener word, a separator inside quoted text before an opener word (`echo "a; open b"`, `echo "(a) else open b"`), an opener word passed as an argument after `powershell -File` and its script, and a launch method's or `child_process`'s name inside a string.

## Invariants & boundaries

- The page stays one self-contained `index.html` that opens straight from disk: no build step, no external scripts, no runtime dependencies. The only external request is the optional Google Fonts stylesheet.
- Every particle renders the same way at every camera angle: text and ambient particles get the same light, colour, size and focus at every eye and everywhere else, and nothing in the scene brightens as the camera nears an eye. The words become obvious only because the particles line up there (owner directive, 2026-10-11: "They need to be glowing consistently no matter what angle. The words should be entirely depending on the right angle to be obvious.").
- The particles are drawn in one additive pass that the test-only layers split exactly: ONE/ONE blending into the 8-bit canvas, no depth buffer, depth of field computed per sprite, and `layer=text` and `layer=ambient` each drawing one of the two ranges the shipped draw covers. `textof=<name>` narrows `layer=text` to one message's part of its range, and `relocate=<name>` moves only that message's particles, so its `layer=ambient` holds every other particle where the base cloud put it. The alike gate's pixel identity rests on this, and on a renderer that does not dither (SwiftShader; the page leaves WebGL's default dithering on), so a change to the draw that turns it red needs the gate rethought, not its bound loosened.
- Each text particle belongs to one message and moves only along its own sight-line from that message's eye, so its projection from there never changes. Ambient drift plus wobble is at most about 0.52 world units. Seen from an eye that is about 0.33σ at the text plane and less beyond it (σ ≈ 1.58 world units, the relocation width in the plans), but about 0.7σ at the main cloud's near edge, 16.5 units in front of the plane. So the density that hides each message holds closely at and beyond its plane and only roughly in front of it.
- Zoom changes the field of view only. The eye stays on the orbit sphere with world-up roll, because moving it breaks the illusion.
- The letters lean right by `SLANT` (14°), each line sheared about its own baseline. The face stands upright. An elevation turn keeps every particle's screen column, so upright stems would show above and below an eye as vertical streaks; leaning ones spread over many columns. The layout gate undoes the lean before it measures and then holds the stems within 4° of upright, so `SLANT_DEG` in `tests/illusion.test.mjs` changes together with `SLANT`. The streak gate holds the el±25 column residual that the lean is for.
- The six messages, their order, their eyes and the start view are part of the contract (`tests/lib/messages.mjs`; `scripts/shoot.mjs` keeps its own copy of the eyes, `EYES`). Hello world's eye stays at (38°, 14°), and the start view is (8°, −16°). Every eye sits at +14° elevation or higher, because an eye within about 20° of another's antipode sees that message mirrored and radially smeared.
- The test contract changes only together with the gates. Query parameters: `az`, `el`, `fov` (degrees), `t` (freezes the particle clock), `tour=0`, `layer=text|ambient`, `textof=<name>` (with `layer=text`: that message's text particles only), `relocate=<name>` (test-only: relocation moves only that message's particles, the same ones onto the same points, and every other particle stays where the base cloud put it, drawn as ambient; the shipped render without it is unchanged), `msg=<name>` (the camera at that message's eye; `az` and `el` override it), `seed`, and the test-only `beta`, a number from 0 to 1 that sets the peak relocation chance for every message (other values keep the default 0.85). The base cloud is the same for every `beta`, and `beta=0` relocates nothing, so a render minus its `beta=0` twin holds only what relocation changed. Read-only `window.__cloud`: `ready`, `frame`, `magic` (hello world's eye), `messages` (`{name, az, el}` in sequence order), `view()`, `alignment()` (degrees from hello world's eye), `mode()` (`tour` for the sequence and capture mode), `target()` (the message the camera holds at or heads for, else null), `capture` (true in capture mode), `counts` (with `byMessage`). DOM ids: `#scene`, `#find`, `#play`, `#readout`, `#hint`, `#nogl`. `#scene` is exposed as a focusable `application` with a role description and a name.
- The sequence glides to each eye in order and holds exactly there. "Find the angle" goes to the next message. `#capture` shows no controls, no cursor and no focus outline and loops the sequence; of the inputs, only Escape ends it. Escape also takes the bare `#capture` anchor out of the address with `history.replaceState`, without a reload, so adding it back starts capture mode again; where the host blocks history changes, the anchor stays and Escape still ends capture mode. Reduced motion switched on mid-glide in Play or capture mode cuts to that glide's eye at once; during a "Find the angle" glide or a snap it lands on that eye at once, with the move's progress taken exactly to its end (review round 2, F94), and a coast stops at once, as at its end (review round 1, F81).
- The page doubles as a claude.ai artifact: one deliberate dark theme with colour tokens on `:root`, no `#key=value` hash state, and it works at 390 px wide. The only hash it reads is the bare `#capture` anchor, which the artifact host passes through, and the only change it makes to the address is to drop that anchor on Escape. At 390 px the widest readout fits beside the buttons with a 0.600 em font; with a wider font the readout gives way (`min-width: 0`, cut short with an ellipsis), so the buttons always stay inside the bar.
- The plan's budget for the page's cost on a GPU: at most 48,000 particles, and sprites that cover at most 3× the screen at 1920×1080 and DPR 2 at the default zoom (`tests/page.test.mjs`). Going past it is a design decision: record the new budget and its reason before changing `PARTICLES` or `MAX_OVERDRAW`, never just to pass.

## Conventions

- Screenshots and other run output go under `tmp/` (ignored) and are deleted once no task needs them.
- To publish the page as an artifact, strip the document wrapper (the doctype, the `html`, `head` and `body` tags, and the charset and viewport metas), because the artifact host supplies them.
